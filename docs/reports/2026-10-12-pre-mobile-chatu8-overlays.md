# PRE 全屏移动端 chatu8 弹窗保护

## 范围与依据

用户报告：手机上正文触摸菜单、长按编辑及图片预览可能被 PRE 内容或内部弹窗盖住。

当前 PRE 实际实现为 `preWebFullscreen.ts`，宿主 iframe 是 `position: fixed; z-index: 900`。它不使用 APP后台版的 enableIframeFullHeight。现场原生 chatu8 菜单、编辑和预览挂在宿主 body，通常为 z-index 10000。

桌面及 Chrome 移动模拟没有重现真实手机的合成层盖住弹窗现象，因此不将该现象归因于一个已确认的浏览器缺陷。修复采用移动端明确让出绘制和命中的保护，避免依赖 iframe 与宿主弹窗的合成层排序。

另有可稳定复现的定位错误：chatu8 在菜单 scale(.85) 入场动画首帧使用 getBoundingClientRect 测量，200px 实际宽度测成 170px，最终菜单超出视口右侧。原始现场中右缘 525px 超过 502px 视口。

## 改动

- 仅 PRE 网页全屏期间，监听宿主 chatu8 正文菜单、需求输入、编辑、预览与确认遮罩的挂载/移除和可见性变化。
- 宽度不超过 760px 或粗指针设备，有上述弹窗可见时，原 iframe 临时 `visibility:hidden; pointer-events:none`。它仍占原尺寸，运行实例、草稿、滚动和宿主消息 DOM 均保留。
- 最后一个弹窗关闭或隐藏后恢复 PRE；嵌套弹窗只关闭一层时继续让出显示；退出全屏、切聊天和卸载释放本功能的属性与样式。
- 桌面保留原来的背景显示，不隐藏 PRE。伊甸终端继续走原有宿主外壳和桥接，不改终端实现。
- 全屏时将正文菜单的入场动画换为插件已有的淡入动画，保持测量尺寸与最终尺寸一致。
- 不抬高整个 iframe，不搬移节点、不修改 chatu8 子仓库、不触发真实 AI 或图片生成。

## 验证

- 新增两个回归场景在修复前失败：低层级宿主弹窗被 iframe 盖住；菜单测量 170px 不等于布局 200px。
- 修复后全屏浏览器测试 10/10 通过，覆盖多个弹窗、隐藏/重新打开、桌面保持原显示、退出清理、iframe 身份/草稿保留、终端和宿主预览。
- 现有 PRE 专项测试 53/53 通过；相关 ESLint、定向生产构建和 diff 空白检查通过。
- 本地构建在酒馆 Chrome 390×700 触屏模拟下：真实三触菜单右缘 365px，位于视口内；三触菜单、长按编辑和图片预览打开时 PRE 为 hidden，关闭后恢复 visible。iframe/contentWindow 身份、草稿、全屏状态保留，聊天仍为 6 条。
- 独立只读代码审查未发现本次改动的实质性回归。
- 真实手机浏览器的最终表现仍需设备复验；Chrome 移动模拟不能等同于用户手机实测。
