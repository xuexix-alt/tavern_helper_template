# 寒冬末日｜庇护所能力映射与变量系统说明

> 用途：给后续开发快速对齐「能力总表、MVU变量、后台脚本、状态栏UI」的实际映射关系。

## 1. 单一数据源（Source of Truth）

- **能力总表文件**：`src/寒冬末日/世界书/寒冬末日/庇护所升级能力.txt`
- 该文件是严格 YAML，包含：
  - `levels`：每级解锁哪些能力 key
  - `abilities`：每个能力 key 的 `name/category/unlock_level/desc/...`
  - `maintenance.imp_support`：维持系统（IMP 阈值、加成、上限）

## 2. MVU 变量中的庇护所字段（运行态）

变量结构定义见：`src/寒冬末日/schema.ts`

`stat_data.庇护所` 关键字段：

| 字段 | 作用 | 备注 |
|---|---|---|
| `庇护所等级` | 当前等级（1-10） | 作为能力解锁主驱动 |
| `庇护所能力` | 已获得能力记录（record） | 运行中会规范化为 `{ [key]: { name } }` |
| `庇护所能力总述` | 结构化能力总结文本 | 由后台脚本实时重算 |
| `接口覆盖等价庇护范围` | 布尔标记 | 表示水/电/暖/安全接口与庇护范围对齐 |
| `接口覆盖范围` | 接口覆盖房间范围 | 脚本从当前庇护范围镜像写入 |
| `当前生存庇护范围` | 真实生存庇护房间范围 | 20/19 层房间列表 |
| `庇护范围变更` | UI 发给脚本的“变更触发器” | 消费后会被清空 |

## 3. 后台脚本逻辑（能力解锁与总述）

脚本文件：`src/寒冬末日/脚本/伊甸后台数据辅助/index.ts`

### 3.1 蓝图解析

- 启动时从 `庇护所升级能力.txt` 解析出运行态蓝图：
  - `abilitiesByLevel`
  - `abilitiesByKey`
  - `levelLabels`
  - `maintenance`

### 3.2 解锁流程

- 主要流程在 `Mvu.events.VARIABLE_UPDATE_ENDED`（last）中执行：
  1. `applyShelterDailyRollIfNeeded(...)`：日更投掷/保底升级
  2. `applyShelterUpgradeRewards(stat_data, shelterLevel)`：按等级补齐能力
  3. `syncShelterDecodedProfile(stat_data)`：重算总述 + 接口覆盖字段

- 额外“开机自愈”逻辑：
  - `syncLatestShelterProfileOnBoot()`
  - 脚本启动后会对 `latest` 楼层做一次能力与总述同步，避免旧档要等下一轮消息才修正。

### 3.3 能力记录规范化

- `normalizeShelterAbilityRecordInPlace` 会统一能力名（引号、空格、全角括号等），避免同技能重复 key。
- 兼容旧数据：同时识别 key 与 value.name。

### 3.4 总述文案统计口径

- 总述分类统计来自**总表能力命中数**（按 category 统计）。
- 若存在不在总表的旧能力，会追加显示：`未入总表能力X项`。

## 4. UI 映射逻辑（技能卡牌）

界面文件：

- `src/寒冬末日/界面/状态栏/components/ShelterSection.vue`
- `src/寒冬末日/界面不含正文剧情/状态栏/components/ShelterSection.vue`

### 4.1 卡牌来源

- 卡牌列表来自能力总表 `abilities`（不是直接遍历变量）。

### 4.2 解锁判定（当前实现）

为避免旧档错位导致“全灰”，判定采取三层：

1. `rawHit`：变量对象中是否存在该能力 key
2. `name/key` 归一化匹配（兼容旧写法）
3. **等级兜底**：`currentLevel >= item.unlock_level` 直接视为已解锁

> 结论：只要等级满足，卡牌至少会点亮，不再依赖历史能力表是否干净。

### 4.3 颜色与价值层级

- 价值层级推导：
  - `基础`: Lv 1-4
  - `关键`: Lv 5-7
  - `核心`: Lv 8-10

- 当前颜色映射（已按最新需求对调）：
  - `基础` → 绿
  - `关键` → 紫
  - `核心` → 金橙

- 图例文案已同步为：`基础（绿）｜关键（紫）｜核心（金橙）`

## 5. initvar 瘦身策略（已采用）

文件：`src/寒冬末日/世界书/寒冬末日/[initvar].yaml`

当前建议：

- 不在 initvar 预填整块 `庇护所能力`
- 不预填 `主线任务.情报碎片`
- 删除明显空容器（如空对象）

理由：

- 能力由总表+脚本同步自动生成
- 情报碎片由任务脚本自动播种
- schema.prefault 会补足基础结构

## 6. 开发改动 checklist

### 改能力内容/解锁节奏

1. 改 `庇护所升级能力.txt`（优先）
2. 校验 `levels.unlocks` 与 `abilities` key 一致
3. 刷新脚本/触发一次变量更新，检查：
   - `庇护所能力总述`
   - 卡牌点亮
   - 分类计数

### 改卡牌视觉（只改显示）

1. 改 `ShelterSection.vue`（逻辑）
2. 改 `global.css`（样式）
3. 两套界面分支同步改：
   - `界面/状态栏`
   - `界面不含正文剧情/状态栏`

### 改变量语义（涉及存档兼容）

1. 改 `schema.ts`
2. 改后台同步脚本（`index.ts`）
3. 补兼容迁移逻辑（优先“非破坏式”）

## 7. 常见问题与排查

### 现象：总述有数量，卡牌没点亮

- 先看是否是旧档能力 key/name 不一致
- 现实现已加等级兜底；若仍异常，优先确认是否加载了旧 dist/旧粘贴页面

### 现象：分类统计全 0 但总数很大

- 说明变量里存在“未入总表”的旧能力项
- 现在总述会显示 `未入总表能力X项`

### 现象：改了总表但 UI 不变

- 多半是加载缓存/旧注入内容
- 需要重载对应 iframe 或重新注入最新 dist/paste

---

如果下次继续开发，建议先从这三个点检查：

1. `庇护所升级能力.txt` 的 key 是否正确
2. `stat_data.庇护所.庇护所等级` 是否正确
3. 当前界面是否是最新打包产物（不是旧缓存）
