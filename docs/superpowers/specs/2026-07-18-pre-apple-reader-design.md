# PRE APPLE 阅读器设计规范

**状态：** 规格审查已通过，待用户书面确认  
**适用范围：** `same-layer-pre` 的 `APPLE`、`APPLE-SKY`、`APPLE-MINT`、`APPLE-LAVENDER`、`APPLE-SAND`、`APPLE-ROSE` 主题档位  
**不适用范围：** 默认 `amber`（琥珀）及其他非 APPLE 主题

## 1. 目标

将 PRE 的 APPLE 系列从“为现有终端式卡片换皮”重构为内容优先的阅读器：当前最新 `ASSISTANT` 正文是界面唯一持续展开的主体；`USER`、历史楼层、角色、画廊、系统、地图和选项退到按需展开的功能层。

本次允许重构 APPLE 档位下的排版与纯 UI 状态，但不修改生成、聊天楼层、MVU、画廊或宿主事件等业务逻辑。全部 APPLE 档位共享同一套结构、材质职责、交互、响应式规则和语义 token 接口。`APPLE` 使用深色中性色阶；其余五个 APPLE 彩色档位使用同一套浅色中性色阶，并只通过强调色与极轻的环境色彼此区分。

## 2. 设计依据与适配原则

本规范不是对原生 SwiftUI 控件的逐像素复制，而是把 Apple 的设计原则翻译为 PRE 网页阅读器可以稳定实现的规则。

- [Get to know the new design system（WWDC25/356）](https://developer.apple.com/videos/play/wwdc2025/356/)：内容是画布，Liquid Glass 是悬浮在内容之上的功能层；层级优先通过排版、分组和空间关系表达，而不是依赖额外底板和边框；跨尺寸保持相同组件解剖和核心行为。
- [Meet Liquid Glass（WWDC25/219）](https://developer.apple.com/videos/play/wwdc2025/219/)：玻璃保留给导航与控制，避免玻璃叠玻璃；Regular 是常规功能层，Clear 只用于媒体内容上方的小型高对比控件；颜色只选择性强调关键动作；需提供减少透明度、增强对比度和减少动态的适配。
- [Design widgets for visionOS（WWDC25/255）](https://developer.apple.com/videos/play/wwdc2025/255/)：借用 Paper、Glass、Elevated、Recessed 的视觉职责区分内容、控制、重要数据和次要信息，但不把 visionOS Widget 直接搬进正文。
- [用户提供的 Sketch 页面](https://www.sketch.com/s/04c24d8b-38fb-4afb-8836-36617e022f02)：仅作为综合色调、明度距离和组件精致度的视觉参考；若与 Apple 官方原则或 PRE 业务层级冲突，以后两者为准。

## 3. 业务信息层级

### 3.1 唯一主内容

当前窗口中最新、可展示的 `ASSISTANT` 楼层是唯一默认完整展开的阅读正文。流式生成中的最新 `ASSISTANT` 同样占据该位置，继续复用现有 `StreamRenderer`，不得因为新排版改变流式内容、图片手势或最终 HTML 的处理路径。

阅读顺序固定为：

1. 当前上下文的 `USER` 单行摘要；
2. 当前最新 `ASSISTANT` 正文；
3. 与当前正文直接相关的少量上下文操作；
4. 底部输入与按需工具入口。

系统消息、旧 `USER`、旧 `ASSISTANT` 不在主阅读区常驻。

### 3.2 当前 USER 手风琴

主阅读区只显示与当前 `ASSISTANT` 直接相关的 `USER`：在已经由现有逻辑筛选出的 `transcriptItems` 中，取当前 `ASSISTANT` 之前最近的一条 `USER`；若最新消息本身是尚未得到回复的 `USER`，则显示这条消息。

- 默认高度为单行，内容转为纯文本、合并空白并省略溢出。
- 点击整行或展开按钮后，在原位展开完整内容；再次点击收起。
- 展开区域使用浅层 Recessed 表面，不使用独立玻璃卡片。
- 展开/收起只属于本地 UI 状态，不写入 MVU、聊天消息或持久化配置。
- 当窗口内没有 `USER` 时，不渲染空手风琴。

### 3.3 空状态和异常状态

- 没有 `ASSISTANT`、但存在最新 `USER`：显示 USER 手风琴和“等待回复”的安静空状态，输入与工具仍可用。
- 完全没有消息：显示现有“等待聊天记录”语义，不制造演示正文。
- 流式生成失败：继续使用现有 `errorMessage` 和日志链，只把错误提示放在当前阅读表面之后，不用错误弹窗替代正文。
- `hidden`、`STREAM`、可重生、可删除等能力完全服从现有 `TranscriptItem`，新展示层不得重新推导业务权限。

## 4. 页面结构

### 4.1 APPLE 专用展示层

`StoryPagePre.vue` 继续持有业务数据、主题、抽屉开关、生成和回退事件。APPLE 系列激活时，主 transcript 区切换到 APPLE 专用展示组件；非 APPLE 主题继续使用现有 `PreTranscriptList.vue` 和 `PreTranscriptMessageCard.vue`，其 DOM、样式和行为不因本次改造改变。

建议组件边界如下：

- `PreAppleReader.vue`
  - 输入：现有 `TranscriptItem[]`、`busy`、回退确认状态和错误信息。
  - 职责：选择并展示当前 USER 摘要、当前 ASSISTANT 正文和 APPLE 阅读空状态。
  - 输出：原样转发 `request-rollback`、`confirm-rollback`、`cancel-rollback`、`regenerate-message`。
- `PreAppleHistoryOverlay.vue`
  - 输入：同一份已加载 `TranscriptItem[]`、选中楼层、业务能力状态。
  - 职责：当前已加载窗口内的历史阅读、单项展开、焦点与关闭行为。
  - 输出：原样转发重新生成和回退事件。
- `StoryPagePre.vue`
  - 只新增 APPLE 的 UI 状态：历史层开关、历史选中楼层、USER 展开状态、打开前的焦点与阅读滚动位置。
  - 不复制聊天读取、生成、删除、画廊或 MVU 逻辑。

组件名称可在实施计划中按现有命名约定微调，但职责边界和“非 APPLE 走原组件”不可改变。

### 4.2 桌面布局

- 页面使用连续环境画布，不再用贯穿窗口的直线边框分割顶栏、正文和底部。
- 当前正文以 720–780px 的阅读列居中；宽屏只增加两侧留白，不扩大正文行宽。
- 顶栏是紧凑 Regular Glass 功能层，品牌与状态降为次级信息。
- 角色和画廊把手悬浮在正文上方的左右边缘，使用 `fixed` 或相对阅读器根节点的脱离文档流定位，不参与 grid/flex 宽度计算。
- 输入框是页面唯一持续存在的大尺寸玻璃浮岛；系统、地图、选项和重生入口组成紧凑工具组，不再放在全宽终端式底板中。

### 4.3 移动布局

- 当前正文自然占满安全区内可用宽度，保留 16px 左右页边距。
- 历史、角色、画廊、系统和地图变为接近全屏的底部 Sheet，最大高度约 `96dvh`；仍保留标题、关闭动作和安全区内边距。
- 左右把手继续悬浮，不得使正文变窄或产生横向滚动。
- 输入浮岛贴近底部安全区，正文末尾必须能滚动到输入区上方，不被遮挡。

## 5. 历史阅读层

### 5.1 入口与数据边界

APPLE 系列下，顶栏“楼层”按钮不再展开现有小型标签菜单，而是打开独立历史阅读层。当前实现的“最新 / N 楼”菜单只切换 `transcriptWindowLabel`，没有真实的数据分页或历史读取逻辑；因此本次不把它误写成业务分页，也不新增聊天读取能力。历史层只展示 `useSameLayerPre.ts` 已提供的 `transcriptItems`（当前最近消息窗口及可能的流式项），顶部可显示已加载条数，但不提供伪分页选择器。

主阅读区和历史层读取同一份已加载消息，但状态彼此独立：主阅读区始终选择其中最新的可展示 `ASSISTANT`，历史层的选中项只控制历史层内部展开内容。点击、切换或关闭历史项不得改变主阅读区的当前项。

非 APPLE 主题的“楼层”菜单和 `transcriptWindowLabel` 行为保持现状。若未来需要读取早于当前窗口的楼层，应单独设计真实历史分页，不属于本规格。

### 5.2 内容组织

- 历史层列出当前已加载窗口内的消息，行级摘要包含角色、楼层号、状态和单行正文摘要。
- 同一时间只允许一个历史项展开，避免重新形成卡片墙。
- 首次打开时默认选择当前最新 `ASSISTANT` 的前一条历史 `ASSISTANT`；如果没有更早的 `ASSISTANT`，选择当前最新可展示项。再次打开时优先恢复本会话最后选中的、仍存在于当前已加载窗口的楼层。
- 当前最新 `ASSISTANT` 可以出现在列表中，但主页面正文不随历史选中项改变。
- 历史项的完整正文沿用当前消息渲染路径；图片、表格、代码和流式标记规则不另写一套。
- 重新生成、回退删除等历史动作放入该项的“更多”菜单，是否显示完全依据现有 `canReroll`、`canDeleteFrom` 等字段。

### 5.3 模态和恢复

- 桌面端为居中的大尺寸 Regular Glass 阅读层，建议宽度上限 1040px、高度上限 88vh；内部正文仍限制为 720–780px。
- 打开时记录主阅读区滚动位置和触发按钮；关闭后恢复滚动位置，并把焦点还给“楼层”按钮。
- 支持关闭按钮、`Escape` 和点击遮罩关闭；回退删除确认中点击遮罩不得绕过现有确认语义。
- 打开期间使用焦点约束与背景滚动锁；不得造成主正文重新挂载、滚动归零或流式渲染重启。

## 6. 功能层与材质职责

材质是一套职责，不是装饰滤镜。每个区域只能承担一种主要材质角色。

| 材质角色 | PRE 用途 | 约束 |
| --- | --- | --- |
| Paper Reading Surface | 当前 ASSISTANT 正文 | 稳定、近不透明、无明显外框；不使用 backdrop blur |
| USER Accordion / Recessed | 当前 USER 展开内容、面板内次要描述和日志 | 通过内凹明度与内阴影退后，不做玻璃卡片 |
| Regular Glass | 顶栏、输入浮岛、历史层、角色/画廊抽屉、系统/地图面板 | 悬浮在内容之上；保证文字对比和背景分离 |
| Elevated Widget | 已打开功能面板中的关键指标或当前选中模块 | 少量使用，通过表面提升和阴影突出 |
| Recessed Widget | 功能面板中的次要数据、描述、日志 | 明度低于所在面板，避免每项描边 |
| Clear Glass | 图片预览上方的小型关闭、翻页、缩放控件 | 仅用于媒体丰富背景；必须有局部 dimming；禁止用于正文和密集文本 |

强制规则：

- 禁止 glass-on-glass。玻璃容器内部的按钮和分组使用填充、亮度、留白、vibrancy 与阴影表达，不再套一层玻璃。
- 不用直角划线和高饱和描边划分常规区域；需要边界时优先使用间距、表面明度和单一 scroll-edge blur。
- 同一滚动视图最多一个 scroll-edge 效果，不叠加 soft/hard 效果。
- 圆角遵循同心关系：外层半径减去内边距得到内层半径；主要浮层约 24–30px，常规分组约 16–20px，小型按钮使用圆角矩形或胶囊。
- 胶囊只用于突出动作、短标签和触控友好控件；高密度桌面信息不得全部胶囊化。

## 7. 色彩与亮度系统

### 7.1 已选亮度基线：B「柔和中间调」

正文与环境的关系优先于主题色。禁止纯黑画布、纯白大面积背景和整页彩色染底。

| 语义层 | 浅色 APPLE 变体 | 深色 APPLE |
| --- | --- | --- |
| Canvas | `#EDEEF2` | `#161618` |
| Paper | `#F9F9FB` | `#222225` |
| Elevated Surface | `#FFFFFF` | `#2C2C2E` |
| Primary Label | `#1D1D1F` | `#F5F5F7` |
| Secondary Label | `#6E6E73` | `#AEAEB2` |
| Separator | 黑色 8%–12% | 白色 10%–14% |

实现时允许为实际宿主背景、浏览器混色和对比度做小幅校准，但必须保留 Canvas → Paper → Elevated 的相邻明度关系，不得回到“黑底亮卡”或“灰底纯白卡”的突兀跳变。

### 7.2 APPLE 档位

| 档位 | 外观基线 | Accent | 环境色规则 |
| --- | --- | --- | --- |
| `APPLE` | 深色 B | `#0A84FF` | 深色石墨，只允许极轻蓝色环境反射 |
| `APPLE-SKY` | 浅色 B | `#007AFF` | 天空蓝 wash |
| `APPLE-MINT` | 浅色 B | `#00C7BE` | 薄荷 wash |
| `APPLE-LAVENDER` | 浅色 B | `#AF52DE` | 薰衣草 wash |
| `APPLE-SAND` | 浅色 B | `#FF9500` | 暖沙 wash |
| `APPLE-ROSE` | 浅色 B | `#FF2D55` | 玫瑰 wash |

- Accent 仅用于主动作、选中态、焦点和极少状态反馈，不作为普通正文边框。
- 环境 wash 控制在约 2%–4%，只出现在画布边缘、玻璃反射或局部氛围中，不进入 Paper 正文底色。
- 普通按钮保持中性；危险动作使用系统红语义，不被主题 Accent 替换。
- 所有档位共享同一套语义 token。禁止为六个档位复制整段组件 CSS。

### 7.3 玻璃可见性

玻璃不能只靠 `backdrop-filter`：它需要半透明表面、细微顶部高光、环境反射、柔和外阴影和与 Canvas 的亮度差共同成立。背景过于单一时仍应能看出功能层轮廓；减少透明度时退化为高不透明表面，而不是消失。

## 8. 排版与空间

- 字体栈：`-apple-system, BlinkMacSystemFont, "SF Pro Text", "PingFang SC", "Microsoft YaHei", sans-serif`。不远程加载字体。
- 当前 ASSISTANT 正文：桌面 17px、移动 16px，行高约 1.8；实现校准范围为 16–17px / 1.75–1.9。
- 阅读列：桌面 720–780px；中文正文以约 38–44 个全角字符的舒适行长为目标，媒体和表格可在安全范围内适当放宽。
- 段落间距约 1em。保留当前两字符首行缩进语义，但标题、列表、表格、代码和媒体不缩进。
- 楼层、角色、时间、状态等元信息使用 12–13px 次级标签；不使用等宽字体营造终端感。
- 等宽字体只用于日志、命令、代码和明确的诊断标识。
- 使用 8pt 空间节奏：正文内部以 16/24px 为主，功能层以 8/12/16px 为主，大区之间使用 24/32px。
- 文字和图标以光学居中为准；不要为了数学居中破坏视觉平衡。

## 9. 控件与交互

- 指针按下即产生反馈，按压反馈不超过 120ms；可使用约 `scale(0.97–0.99)`、高光或亮度变化，不能等待点击完成才反馈。
- 常规展开、弹出和 Sheet 过渡为 180–320ms；使用轻微、可中断的弹簧曲线，不做持续装饰动画。
- 弹出菜单和手风琴从触发源建立空间关系；关闭路径与打开路径一致。
- 控件在桌面端最小可点击高度 32px，触控环境目标区域不小于 44px。
- 主动作单独着色；相关次级动作可以共享中性容器，但图标按钮与文字按钮不得视觉粘连成一个无法辨认的控件。
- 不明确的图标必须带文字标签或可访问名称。
- 当前 ASSISTANT 的非主要动作放入“更多”菜单；底部既有“重生”入口仍保留，不重复制造第二个常驻主按钮。
- 角色、画廊、系统、地图、选项打开时不挤压正文。关闭后正文宽度、位置和滚动状态不变。

## 10. 可访问性

- 所有弹层使用正确的 `dialog`/`aria-modal` 语义、可读标题、焦点约束、`Escape` 关闭与焦点归还。
- USER 手风琴使用 `aria-expanded`、`aria-controls`，摘要按钮可通过键盘操作。
- `:focus-visible` 焦点环至少 2px，不能只靠颜色变化表示焦点。
- `prefers-reduced-motion: reduce`：取消回弹和大位移，过渡改为不超过 160ms 的淡入淡出；流式正文不受影响。
- `prefers-reduced-transparency: reduce`：Regular Glass 表面不透明度至少 0.92，关闭依赖背景内容的透明效果。
- `prefers-contrast: more`：增强文字、分隔与焦点，不通过新增大量常驻边框破坏结构。
- 正文与 Paper 的普通文字对比度至少 7:1；次要文字至少满足 WCAG AA。

## 11. 响应式与连续性

- 必测视口：375、768、1024、1440px。
- 任何目标宽度下都必须满足 `scrollWidth === clientWidth`；图片、表格、代码、长 URL 不得撑开页面。
- 桌面历史层是居中阅读浮层，角色/画廊是左右浮动抽屉。
- 移动端历史、角色、画廊、系统、地图使用近全屏底部 Sheet；组件职责和核心动作与桌面一致，只改变空间表达。
- 切换视口尺寸不得丢失当前 USER 展开状态、历史选中项或主阅读滚动位置。
- 左右把手加入、移除、打开、关闭前后，正文容器的宽度和左右坐标差值不超过 1px。

## 12. 状态与数据流不变量

以下能力必须继续沿用现有来源和事件，禁止在 APPLE 组件中实现替代逻辑：

- 聊天窗口读取、筛选和流式更新；非 APPLE 现有楼层标签菜单保持原样；
- 消息生成、取消、重新生成、回退删除及其确认；
- `TranscriptItem` 的权限、阶段、隐藏和流式状态；
- MVU 变量读写与角色数据来源；
- 画廊图片真相、图片引用、手势转发和角色立绘分配；
- 系统日志、地图、选项、开局、Beta 诊断；
- 宿主事件名、插件接口和错误处理；
- 默认主题 `amber` 与非 APPLE 主题的 DOM、视觉和交互。

主题切换时允许 APPLE 展示层挂载或卸载，但不清空业务状态。APPLE 内部 UI 状态可以在离开 APPLE 时重置；返回后默认聚焦最新正文。

## 13. 测试与验收

### 13.1 结构验收

1. 默认主题仍为 `amber`；六个 APPLE 档位可选，并共享 APPLE 基础类与展示结构。
2. APPLE 下只完整展示当前最新 `ASSISTANT`；相关 `USER` 默认为单行摘要，旧消息不在主区形成卡片列表。
3. 非 APPLE 仍渲染现有 `PreTranscriptList`，现有主题不受 APPLE 结构和样式泄漏影响。
4. 没有 ASSISTANT、没有 USER、流式中、错误、hidden 和长内容场景均有明确表现。

### 13.2 历史层验收

1. APPLE 顶栏“楼层”打开历史阅读层，展示当前已加载的 `transcriptItems`；不新增或伪造历史分页。
2. 历史列表同一时间只展开一项；选中历史不会替换主页面当前正文。
3. 历史项动作遵守现有权限并转发原事件；关闭后主正文滚动与焦点恢复。
4. `Escape`、遮罩、关闭按钮、焦点约束和移动端 Sheet 均可操作。

### 13.3 视觉验收

1. `APPLE` 使用 B 深色中性色阶，五个浅色档位共享 B 浅色中性色阶；两类外观都保持 Canvas、Paper、Elevated 的稳定明度关系。
2. 五个浅色档位彼此只改变 Accent 与 2%–4% 环境 wash；深色 `APPLE` 使用深色专属中性色阶和系统蓝 Accent；所有档位的 Paper 都不被主题色染色。
3. 当前正文是首要视觉焦点；顶栏、元信息、把手和工具不会抢夺注意力。
4. 玻璃清晰可见但不影响文字；无 glass-on-glass、无贯穿式硬分隔、无常驻蓝色外框。
5. 正文桌面为 16–17px / 1.75–1.9，阅读列 720–780px；移动端为 16px 左右并无横向滚动。

### 13.4 功能与回归验收

1. 生成、流式显示、重生、历史重生、回退删除、取消生成均与改造前一致。
2. MVU、角色抽屉、画廊、图片手势、系统、地图、选项、开局和 Beta 诊断可用。
3. 375、768、1024、1440px 下把手不占正文宽度，输入区不遮挡正文尾部。
4. reduced-motion、reduced-transparency、more-contrast 和键盘导航通过浏览器检查。
5. 通过现有 PRE 测试、必要的新展示契约测试、组件 token 检查、类型检查、生产构建和 `git diff --check`。
