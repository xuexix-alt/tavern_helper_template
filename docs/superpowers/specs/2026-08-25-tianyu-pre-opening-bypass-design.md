# 天欲太和录 PRE 开局绕过设计

## 目标

不修改 `same-layer-pre`，让“天欲太和录”新聊天在只有 `mes=0` 时自动创建一条可见的正式序章作为 assistant `mes=1`，从而满足 PRE 已存在正文章节的判定并跳过 opening 设置页。同时把同名世界书加入 `tavern_sync.yaml`。

## 方案

- 在天欲太和录现有的变量结构脚本中加入专用序章启动逻辑，避免额外安装第二个脚本。
- 脚本等待 MVU 可用并注册 Schema 后，仅在 `getLastMessageId() === 0` 时运行。
- 从 `mes=0` 读取 MVU 数据，用天欲太和录 Schema 校验、补齐 `stat_data`，再把该数据深拷贝给新建的 `mes=1`。
- `mes=1` 使用用户提供的《阴阳江湖序章》全文，角色为 assistant、可见、不调用模型。
- 使用进程内执行锁并在创建前后二次检查楼层号，避免初次加载与聊天事件重入造成重复序章。
- 已有 `mes>=1` 的聊天完全不修改；失败时只记录明确错误，不删除或覆盖聊天内容。

## PRE 绕过依据

PRE 当前只在忙碌结束后，同时满足“`mes>0` 没有非空 assistant”且“`mes>0` 没有 user”时显示 opening。它不读取任何 MVU 跳过变量。因此创建可见 assistant `mes=1` 是无需修改 PRE 的最小稳定入口。

- 类型：`世界书`
- 酒馆中的名称：`天欲太和录`
- 本地文件路径：`src/天欲太和录/世界书/index.yaml`
- 导出文件路径：`src/天欲太和录`

## 验证

- 自动化测试证明：`mes=0` 创建一次可见 assistant `mes=1`；`mes>=1` 不创建；并发调用不重复。
- 校验新建楼层携带通过 Schema 的 `stat_data`，序章文本与用户提供内容一致。
- 执行天欲太和录定向 schema dump 和生产构建。
- 用 `tavern_sync bundle 天欲太和录` 验证配置，再推送同名世界书。
- 新建酒馆聊天验证楼层为 `0, 1`、`mes=1` 可见且 PRE opening 不再出现。
