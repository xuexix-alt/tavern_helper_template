# 小手机组件健康检查设计

## 目标

为酒馆助手脚本页手动加载的 10 个小手机脚本提供一次性启动检查，并修正寒冬微信发送在移动端对 iframe 内全局 `generateRaw` 的依赖。

## 检查范围

检查 `00运行时管理器`、`10平台服务`、`20数据与同步`、`30AI与调度`、`40手机外壳`、`50通信与情报APP`、`60智能情报`、`70微信APP适配器`、`90主适配器`、`小手机-90寒冬适配器`。每项显示预期版本、实际版本以及 `READY`、`REGISTERED`、`ERROR` 或缺失状态。

`60智能情报`、`70微信APP适配器` 和通用 `90主适配器` 当前不属于寒冬适配器的初始化依赖图。检测器保留这一事实，将它们标为待命组件；不会为了让检查变绿而擅自初始化实验模块。

## 架构

公共运行时向只读 API 暴露模块注册快照，模块注册表负责提供真实 manifest 和实例状态。`00运行时管理器` 在最后一次模块注册后延迟汇总，使用 toastr 弹出一次通知：完整时显示检测数量、活动数量和待命数量，异常时列出缺失、版本不符或核心未就绪的组件。

组件期望清单和报告计算放在独立的 `componentHealth.ts`，避免将业务规则塞进运行时生命周期。运行时自身作为第 10 项由检查器直接标记为就绪。

## 移动端微信发送

寒冬适配器不再直接捕获当前 iframe 的全局 `generateRaw` 和 `stopGenerationById`。它复用平台 `tavernApiAdapter`，按 `window.parent`、`window.top`、`window` 顺序解析 `TavernHelper`，与 `70微信APP适配器` 的宿主调用方式保持一致。世界书预写、AI 回写和失败状态行为保持不变。

## 错误与通知

- 完整且版本一致：success，一次性显示 `10/10`、活动和待命数量。
- 缺失、版本不符、核心非 READY：warning，正文逐项列出问题。
- 通知失败不得影响运行时或手机启动，只写控制台警告。
- 报告只含模块 ID、版本和状态，不暴露 API 密钥、提示词或聊天内容。

## 验证

为模块快照、健康报告四种结果、通知去重以及移动端宿主 API 解析添加回归测试。随后运行小手机平台测试、针对性生产构建、`git diff --check`，并核对生成 bundle 包含健康检查文本和宿主 API 解析逻辑。
