# 同层版接入 `st-chatu8` 原生图片链重构设计

## 背景

当前同层版的正文生图功能已经证明：

- 生图请求事件可以接到
- 插件自己的图库与隐写缓存可以工作
- 同层版也能把图片显示出来

但业务链仍然是分裂的：

- 插件原生链负责生成、DB、恢复
- 同层版又维护了一套平行的持久化与显示语义

这导致了几个长期无法稳定消除的问题：

- `getSavedImageMatches` 反复报错
- 图片在 UI 层持久化，但没有真正进入 chat 原生链
- 图片堆在正文末尾，而不是由插件恢复回原位
- 图片显示出来了，但无法走插件原生交互

## 目标

把同层版正文生图功能重构为：

- **插件原生真源唯一化**
- **同层版只做桥接，不再造平行实体**

最终目标：

- 正文图片的唯一业务真源是：
  - `extra.images`
  - `lockedTags`
  - 正文 `image###...###` token
  - 插件原生恢复出来的 DOM
- 同层版自身的 `data.stream_demo.generated_images` 只保留兼容价值，不再作为主链

## 真源定义

### 唯一业务真源

后续图片业务只认以下链路：

1. **消息原生字段**
   - `message.extra.images`
   - `message.extra.lockedTags`
   - `message.message` 中的 `image###...###`

2. **插件原生恢复链**
   - `findAndReplaceInElement`
   - `getSavedImageMatches`
   - `fuzzyMatchLine`
   - `.st-chatu8-image-button`
   - `.st-chatu8-image-span`

3. **插件原生二进制缓存**
   - `chatu8_gallery`
   - `jiuguanStorage`
   - `Stego` 清单

### 降级为兼容字段

以下字段不再作为主链：

- `data.stream_demo.generated_images`

它可以继续保留：

- 作为过渡兼容
- 作为调试与图廊兜底

但不允许继续成为“正文显示是否成功”的判定依据。

## 重构原则

### 1. 如无必要，勿增实体

同层版不再新增独立图片业务模型。

不再新增：

- 新的图片消息字段规范
- 新的平行缓存索引
- 新的正文图片恢复协议

所有图片链路都应围绕插件已有结构展开。

### 2. 同层版只做桥接器

同层版职责只保留三类：

1. **触发桥接**
   - 在正确楼层触发插件原生正文生图入口

2. **响应落盘桥接**
   - 在收到 `generate-image-response` 后
   - 把结果补写进插件原生消息字段

3. **交互桥接**
   - 同层版中的图片点击/双击/触摸
   - 优先映射到插件原生恢复出来的 DOM 节点

### 3. 恢复优先级必须反转

后续正文显示顺序应改为：

1. 优先找插件原生恢复 DOM
2. 找不到时再考虑兼容层

而不是继续：

1. 先渲染同层版自己的图片 DOM
2. 再尝试和插件原生链对齐

## 目标链路设计

### A. 触发入口

正文生图触发仍沿用插件原生事件与入口：

- `generate-image-request`
- `generate-image-response`

但楼层识别与触发目标必须以“宿主原生消息节点”优先：

- 宿主 `mes_text`
- 宿主 `.st-chatu8-image-button`
- 宿主 `.st-chatu8-image-span`

不再把同层版自己的图片 DOM 当作原生触发目标。

### B. 响应落盘

每张图回来后，统一落到插件原生消息链：

#### 必写字段

`extra.images[swipe_id][]`

每条至少保证：

- `requestId`
- `request_id`
- `prompt`
- `tag`
- `regex`
- `src`
- `image`
- `imageData`
- `alt`

#### 同步字段

- `extra.lockedTags`
- 正文 `image###...###`

#### 字段语义

- `tag`
  - 使用 prompt body
  - 不能写空

- `regex`
  - 由同层版已有 `anchorText` 转换
  - 目标是让插件 `fuzzyMatchLine` 能恢复到正文对应段落

### C. 正文 token

`image###...###` 必须真正进入消息正文。

规则：

- 优先按 `anchorText` 插回 `<content>` 对应段落后
- 找不到锚点才回退到 `<content>` 末尾
- 重复 token 不允许重复写入

### D. 恢复链

同层版正文后续显示逻辑改为：

1. 宿主里已存在 `.st-chatu8-image-span`
   - 直接视为成功恢复
   - 不再自己额外渲染平行图片节点

2. 若插件原生恢复失败
   - 只保留极薄兼容 fallback
   - 但不能覆盖插件原生链

### E. 图片交互

图片交互以后只桥接到插件原生节点：

- 单击：原生预览 / 图片点击
- 双击：原生菜单 / 重生成
- 移动端触摸：原生点击链

如果同层版页面上当前图片还只是兼容层图片：

- 允许显示
- 但不应宣称业务成功

## 失败点复盘

### 已确认失败点

1. `getSavedImageMatches` 报错
   - 说明插件恢复链读到的消息图片条目结构不完整

2. UI 有图但 chat 链不完整
   - 说明图片只进入兼容层，不是真正进入插件原生消息链

3. 图片堆在末尾
   - 说明 `regex` / 锚点恢复链没有真正接通

4. 图片不能交互
   - 说明当前用户操作的是同层版图片 DOM，不是插件原生恢复 DOM

## 拆分实施

### 阶段 1：收拢真源

- 停止继续增强 `data.stream_demo.generated_images` 主链能力
- 所有新结果优先写插件原生字段

### 阶段 2：修复恢复输入

- 统一清洗旧消息中的 `extra.images`
- 补齐插件恢复所需字段
- 保证 `regex/tag/requestId` 等字段不缺失

### 阶段 3：修复正文回写

- token 真正写回消息正文
- `anchorText -> regex`

### 阶段 4：修复原位恢复

- 让插件原生恢复 DOM 成为正文唯一主显示

### 阶段 5：修复交互

- 图片操作只对接插件原生 DOM

## 验收标准

满足以下条件才算完成：

1. 打开已有聊天时，不再持续报：
   - `getSavedImageMatches`
   - `fuzzyMatchLine ... trim`

2. 生图后：
   - 图片进入 `extra.images`
   - 对应 token 进入正文
   - 图廊正常显示

3. 重载聊天后：
   - 图片通过插件原生恢复链回到正文原位
   - 不只是堆在末尾

4. 点击或双击图片时：
   - 能走插件原生交互
   - 不只是同层版自定义节点响应

5. 同层版无须维护独立图片真源

## 当前结论

后续开发不再继续“修旧补丁”，而是以插件原生链为中心重构：

- 原生事件
- 原生消息字段
- 原生恢复 DOM
- 原生缓存

同层版退回为桥接层。
