# 小手机本机 API 设置设计

## 目标

完善小手机“设置”页，使 OpenAI-compatible 配置能够保存、读取模型列表，并在同一浏览器的所有角色卡之间共享。联系人等剧情数据仍按聊天存档隔离，不受本设计影响。

## 当前问题

- 设置页没有 API Key 输入与保存入口。
- 平台调用 AI 时依赖设置存储中的密钥，因此当前 OpenAI-compatible 链路始终缺少凭据。
- 设置页没有调用兼容接口模型列表的按钮。
- 现有设置键按角色卡分区，不满足所有角色卡共用一套本机配置的要求。

## 设计

### 本机全局存储

使用浏览器 `localStorage` 保存一套小手机全局配置，不绑定聊天号或角色卡。公开设置与 API Key 使用不同的存储键：公开设置包含 provider、API URL、模型、生成参数、主题和通知开关；密钥只进入独立 secret 存储，不进入公开设置对象、诊断信息或聊天变量。

首次读取全局配置为空时，可从当前角色卡的旧版设置键迁移一次，避免已有配置无故丢失。此后所有角色卡读取同一全局键。

### 设置界面

OpenAI-compatible 档位显示：

- API URL 输入框；
- API Key 密码框；
- “拉取模型列表”按钮；
- 模型输入框及可选择的模型列表；
- “保存配置”按钮；
- 已保存密钥提示与“清除 Key”按钮。

API Key 输入框默认留空。留空保存表示保留已经保存的密钥，而不是清空；只有点击“清除 Key”才删除密钥。

### 模型列表

拉取模型时优先使用当前输入框中的 API Key；输入框为空时使用本机已保存的密钥。API URL 规范化到兼容的 `/v1/models` 地址，并发送 Bearer 认证请求。响应读取 `data` 数组中的 `id`（兼容 `name`），去重后显示供用户选择。

拉取失败、响应格式错误或缺少 URL/Key 时，在设置页给出可见错误，并恢复按钮状态；不得抛出未处理异常或阻塞酒馆助手页面。

### 保存链路

保存按钮先校验生成参数 JSON，再写入公开设置；如果 API Key 输入不为空，则同时更新独立 secret 存储。保存成功后显示明确反馈，重新打开设置页能恢复公开配置并显示“已保存 Key”，但不回填明文密钥。

## 兼容性与边界

- 不把 API 配置写入聊天变量、MVU 快照或联系人存档。
- 不改动联系人、群聊和剧情数据的存储作用域。
- 不在日志、错误信息、公开设置或诊断页面中显示 API Key。
- 保持 Tavern provider 的现有行为；模型拉取功能仅服务于 OpenAI-compatible 配置。

## 验证

- 设置存储测试：不同角色卡实例读取同一公开配置与密钥。
- 迁移测试：全局键为空时读取旧角色卡配置。
- 密钥隔离测试：公开配置序列化结果不含 API Key。
- 模型接口测试：URL 规范化、Bearer 请求、模型解析、错误处理。
- 设置页测试：API Key、拉取模型、选择模型、保存与清除按钮均接入服务。
- 构建小手机平台与寒冬适配器，并在现场确认重新打开设置后配置仍存在。
