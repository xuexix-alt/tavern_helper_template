# 寒冬末日“伊甸终端”联系人设计

## 目标

把寒冬小手机简化为“伊甸终端”。MVU 只提供当前存档中的人物与全局剧情事实；联系人、私聊资格和群成员由玩家手动管理，并按当前聊天存档持久化到 PhoneDB。

## 人物候选来源

唯一数据源是当前聊天 `message_id: 'latest'` 的 `stat_data`。

- 排除固定根字段：`世界`、`通讯网络`、`庇护所`、`伊甸一次性指令`、`房间`、`主线任务`、`临时NPC`、`楼层其他住户`。
- 其余顶层值必须是对象且拥有 `登场状态` 字段，才认定为主要人物；字段值为“登场”或“离场”都可进入候选。
- `/临时NPC/*` 独立遍历；值为对象且拥有 `登场状态` 时进入候选。
- 显示名优先使用对象内非空 `姓名`，否则回退到对象 key。
- 人物身份使用现有 `main:<key>` 与 `temporary:<key>`；临时 NPC 转正继续使用既有身份迁移机制。

## 联系人与群成员

PhoneDB 现有 `contactPrefs` 表保存联系人记录，所有记录携带当前 runtime 的 `sessionKey`，不同聊天存档严格隔离。

联系人记录保存人物身份、最后已知姓名、添加时间和伊甸群邀请状态。通讯录分成：

1. 已添加联系人：可进入私聊，并可手动邀请进入或移出“伊甸住户群”。
2. 可添加人物：来自最新 MVU 候选，点击后才成为长期联系人。

人物离场不会删除长期联系人。人物暂时不在最新变量中时仍保留联系人和历史会话，使用最后已知姓名；后续重新出现时刷新姓名。私聊资格只要求该身份已经由玩家添加，不再检查人物是否登场、Imp、终端型号或个人信号。

“伊甸住户群”的参与者完全来自当前存档中被手动邀请的联系人。邀请和移出群聊不写回 MVU，也不依赖庇护所技能或伊甸终端 T2/T4。

## 移除角色通讯变量

角色级 `通讯` 对象不再属于业务数据。将从以下当前模板中移除：

- `schema.ts` 的角色 Schema 与默认值；
- `[initvar].yaml` 的所有主要角色；
- 临时 NPC 结构示意；
- MVU 更新规则、输出检查和示例 Patch；
- 寒冬适配器中的个人终端、信号、联系资格与 T2/T4 校验。

旧存档残留的 `通讯` 字段视为未知兼容数据：手机忽略它，不报错、不要求迁移、不写回。候选人物识别不依赖 `姓名` 或 `通讯`，因此兼容缺少这些新增字段的旧 initvar。

全局 `通讯网络` 保留，继续作为剧情、广播和系统状态事实，但不再决定人物是否为联系人。

## 产品名称与 Lv1 能力

寒冬适配器向通用 PhoneShell 提供品牌名“伊甸终端”；外壳标题、无障碍名称和 same-layer-pre 入口文案统一显示该名称。通用平台保持可复用默认值，不把寒冬品牌硬编码进共享模块。

新增能力键 `social.eden_terminal_t1`，显示名为“📱伊甸终端”，加入庇护所 Lv1 解锁表，因此 Lv1 存档在现有能力同步流程后默认拥有。手机业务不再依赖旧的 `social.shift_ration_protocol_t2` 或 `social.eden_phone_mass_t4`；旧存档残留能力可继续存在，但不参与联系人或群聊判断。

## 错误与生命周期

- PhoneDB 写入失败时不乐观更新 UI，显示错误并允许重试。
- 重复添加、重复邀请和重复移出必须幂等。
- 会话切换后，所有联系人操作重新捕获并校验 `sessionKey`，不得写入旧存档。
- 候选人物与长期联系人合并时按身份去重；同名不同身份不得自动合并。

## 验证

- 新旧 MVU 均能排除系统字段并提取主要人物和临时 NPC。
- 缺少 `姓名` 时使用 key；缺少 `通讯` 时无异常。
- 添加联系人、刷新、重新打开终端后仍存在，且其他聊天存档不可见。
- 私聊只接受已添加联系人；邀请与移出会更新伊甸群成员。
- 临时 NPC 转正后联系人、会话和群成员身份随既有迁移迁移。
- Lv1 能力同步包含“伊甸终端”，手机 UI 与 Pre 入口品牌一致。
- 相关单元测试、源码契约测试和范围化生产构建通过。
