## 📋 插件事件系统概述

### 插件暴露的事件

根据 `docs/前端接入插件的说明.txt`，插件只暴露了两个事件：

```javascript
const EventType = {
    GENERATE_IMAGE_REQUEST: 'generate-image-request',   // 发送生图请求
    GENERATE_IMAGE_RESPONSE: 'generate-image-response', // 接收生图响应
};
```

**注意**：插件**没有**暴露 `st-chatu8-images-rendered` 事件（图片渲染完成通知）

### 时序图

```

  ↓

  ↓
图片生成服务处理
  ↓

  ↓

  1. syncTranscriptItemsFromHostData()      → 从宿主DOM读取图片
  2. discoverRecentNativeGalleryImages()    → 扫描画廊图片

  ↓

  ↓
图片显示在画廊和正文中 ✅
```

## 🔄 完整的图片同步机制

### 触发时机（多层保障）

#### 1. **事件驱动同步**（最快，精确）

- ✅ 响应最快（图片生成完成后立即同步）
- ✅ 精确知道哪个消息有新图片
- ✅ 只同步相关消息（性能最优）

#### 2. **多轮延迟同步**（兜底，覆盖旧消息）

## ⚠️ 为什么没有 `st-chatu8-images-rendered` 事件？

### 问题

插件没有暴露"图片渲染完成"的事件，只有"图片生成完成"的事件。

### 差异

```
图片生成完成（有事件）:
  插件收到图片base64数据 → 发送 generate-image-response

图片渲染完成（无事件）:
  插件将图片插入到宿主DOM → ❌ 没有事件通知
```

### 解决方案

我们使用**多层触发机制**来弥补这个gap：

1. **事件驱动** + **延迟扫描**：`onResponseSuccess` + 400ms延迟
   - 假设插件在400ms内完成DOM渲染
   
2. **多轮延迟同步**：500ms, 1500ms, 3000ms
   - 覆盖插件渲染延迟
   
3. **主动DOM修复**：检查并触发
   - 如果插件没渲染，手动触发
