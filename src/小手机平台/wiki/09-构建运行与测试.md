# 09 构建运行与测试

## 9.1 环境要求

| 项 | 要求 |
| --- | --- |
| Node.js | 22.x（CI 使用 Node 22；仓库 `dump_schema.ts` 等直接 `node` 运行 .ts，依赖较新的类型剥离支持） |
| 包管理器 | pnpm 10（CI 使用 [pnpm/action-setup](../../../.github/workflows/bundle.yaml) v4.1.0 / version 10） |
| 运行目标 | SillyTavern（酒馆）+ 酒馆助手（Tavern Helper）插件环境（浏览器 iframe） |

```bash
pnpm install
```

## 9.2 构建命令

| 命令 | 作用 |
| --- | --- |
| `pnpm build` | 生产构建（webpack --mode production） |
| `pnpm build:dev` | 开发构建（webpack --mode development） |
| `pnpm watch` | 开发监听（--watch --progress，推荐日常使用） |
| `pnpm lint` / `pnpm lint:fix` | ESLint 检查/修复 |
| `pnpm format` | Prettier 格式化 |
| `pnpm dump` | 将所有 schema.ts 转换为 schema.json |
| `pnpm sync` | tavern_sync：打包/同步配置了的角色卡、世界书、预设 |

### 入口发现规则（[webpack.config.ts](../../../webpack.config.ts)）

- webpack 扫描 `{示例,src}/**/index.{ts,tsx,js,jsx}`，**每个入口目录生成一个构建产物**；存在嵌套 index 时保留最上层（目录去重）
- 小手机平台的 9 个入口分别输出到 `dist/小手机平台/脚本/<名称>/index.js`（+ `.js.map`）
- 同目录存在 `index.html` 时按「前端界面」打包（HTML 内联产物）；小手机平台全部为**脚本项目**（无 html）
- 脚本源码含 `@obfuscate` 注释时启用 webpack-obfuscator 混淆（本平台未使用）
- 第三方库 externals 策略：`jquery->$`、`lodash->_`、`toastr`、`vue`、`yaml`、`zod` 等映射为全局变量；其余裸依赖转换为 `https://testingcf.jsdelivr.net/npm/<pkg>/+esm` CDN 链接（避免重复打包）

### 构建范围与环境变量

| 环境变量 | 作用 |
| --- | --- |
| `TAVERN_BUILD_PREFIXES` | 分号分隔的路径前缀，只构建匹配的入口（见 [webpack.buildScope.cjs](../../../webpack.buildScope.cjs)） |
| `TAVERN_SKIP_GENERATORS=1` | 跳过 schema dump 与 tavern_sync 附加流程 |

只构建小手机平台：

```powershell
$env:TAVERN_BUILD_PREFIXES='src/小手机平台'
$env:TAVERN_SKIP_GENERATORS='1'
pnpm exec webpack --mode development
```

### watch 模式的附加行为

`pnpm watch` 时 webpack 配置自动启用（`TAVERN_SKIP_GENERATORS=1` 可关闭后两项）：

1. **socket.io 热更新服务**：端口 **6621**，编译完成后向已连接的酒馆网页推送 `script_iframe_updated` / `message_iframe_updated` 事件
2. **tavern_sync watch**：spawn `pnpm sync watch all -f`，同步角色卡/世界书/预设配置
3. **schema dump 监听**：chokidar 监听 `src` 下 `schema.ts` 变化并防抖执行 `pnpm dump`

## 9.4 测试

测试位于 [__tests__/](../__tests__/)，共 15 个文件，**不依赖任何测试框架生态**，分为两类：

### `.test.ts`（自包含脚本 + node:assert）

无统一 test runner，`main()` 直跑，成功时输出 `xxx tests passed`。因 tsconfig 的 `types` 未含 node 且模块解析为 bundler，需覆盖编译选项运行（已验证）：

```powershell
$env:TS_NODE_COMPILER_OPTIONS='{"module":"commonjs","moduleResolution":"node"}'
pnpm exec ts-node --transpile-only "src/小手机平台/__tests__/parseRetry.test.ts"
# 输出: parse retry tests passed
```

文件清单（14 个 `.test.ts`）：`runtime.test.ts`（约 1083 行）、`data.test.ts`（约 1160 行，用 fake-indexeddb）、`ai.test.ts`（约 1064 行）、`scheduler.test.ts`（约 1140 行）、`profileCoordinator.test.ts`、`profileAnalysis.test.ts`、`profileBroadcast.test.ts`、`profileSources.test.ts`、`profileWorldbook.test.ts`、`storyExtractor.test.ts`、`roleLore.test.ts`、`parseRetry.test.ts`、`intelligenceService.test.ts`、`storage.test.ts`。

### `.test.js`（node:test 运行器 + 源码静态断言）

如 `shellSource.test.js`：读取 TS 源码做静态断言（禁 innerHTML 等），并用 `typescript.transpileModule` 运行时加载模块配合 FakeElement 测试行为：

```powershell
node "src/小手机平台/__tests__/shellSource.test.js"
# node:test 输出 pass/fail 摘要
```

### 测试特点

- 全部**脱离酒馆环境**可运行：`fake-indexeddb` 提供 IndexedDB、mock 全局 `getChatMessages`、自建 fake SillyTavern 宿主、`node:vm.runInNewContext` 模拟跨 iframe JSON 对象
- 源码契约测试（静态断言）用于锁定安全约束：textContent-only 渲染、微信图标 sha256、ChatLore 与世界书写函数隔离、任务动作禁 `generateRaw/setMvu` 等

## 9.5 CI 与发布

[.github/workflows/bundle.yaml](../../../.github/workflows/bundle.yaml)（push 到 `master/main/20260211`，忽略 `dist/**`）：

1. 删除 dist -> `pnpm install && pnpm check:component-tokens && pnpm format && pnpm build`
2. 以 `[bot] bundle` 提交 dist 产物
3. 自动打版本 tag，让 jsdelivr 基于版本号在 12h 内更新缓存

线上分发：`dist/**/index.js` 经 jsdelivr 访问，酒馆助手脚本中以 `import 'https://testingcf.jsdelivr.net/gh/<user>/<repo>@<tag>/dist/...'` 加载（国内使用 testingcf 镜像）。

## 9.6 集成到角色卡（运行方式）

1. 本地构建小手机平台 6 个必需脚本 + 角色适配器（见 [07](07-脚本入口与模块注册.md) 第 5 节清单）
2. 把各 `dist/**/index.js` 作为**独立脚本**写入角色卡（或用 jsdelivr 链接 import）
3. 脚本可按任意顺序加载：runtime 由 `00运行时管理器` 安装，其余入口经 pending 队列兜底；当 `phone.adapter` 根依赖图完整后自动初始化一次
4. 生成角色卡 PNG：配置 `tavern_sync.yaml` 的角色卡导出路径，运行 `node tavern_sync.mjs bundle '<角色卡名>'`（临时文件生成后原子替换，详见寒冬适配器 README）
