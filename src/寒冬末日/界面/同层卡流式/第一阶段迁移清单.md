# 寒冬末日同层卡流式迁移清单（阶段1：剧情）

## 目标与范围

- 迁移策略：分阶段
- 阶段1：只迁移剧情相关（正文展示、流式状态、选项展示）
- 阶段2：再迁移变量/角色相关（庇护所、任务、角色管理、创作等）

---

## A. `useInjectedData` 的 context 适配版改造清单

> 目标：同一份解析能力既能用于旧的“消息 iframe 页面模式”，也能用于新的“mountStreamingMessages 同层卡模式”。

1. 新增 context 输入通道  
   将 `fetchFromCurrentMessage(isDebug)` 扩展为支持 `message_id + message_raw` 外部输入。  
   推荐新增函数：`parseInjectedTextBySource(raw: string, source: { mode: 'context' | 'message_iframe'; message_id?: number })`。

2. 现有 API 保持兼容  
   继续保留 `useInjectedData()`（内部走 `getCurrentMessageId() + getChatMessages()`），不破坏现有 `src/寒冬末日/界面/状态栏/` 页面。

3. 新增流式专用 composable  
   新增 `useStreamingInjectedData(context)`，直接消费 `injectStreamingMessageContext()` 提供的 `message` 与 `message_id`，避免在流式卡里再调用 `getCurrentMessageId()`。

4. 正文提取改为“主标签 + 排除标签”配置化  
   - 主正文标签：`content/game`
   - 排除标签：`profile/meow_fm/updatevariable/jsonpatch/analysis/...`
   迁移时不要把标签名写死在多个文件里，统一在解析层定义。

5. 增加未闭合标签容错  
   当 `<content>` 有开无闭时，回退为“从开标签后截取到末尾”，避免整段 raw（含模块）误入正文。

6. 解析输出稳定结构  
   标准输出字段建议固定为：
   - `raw`
   - `mainText`
   - `options`
   阶段1 UI 仅消费这三个字段。

7. 调试日志按 message_id 去重  
   沿用你现有 `Set<message_id>` 去重策略，避免流式过程中日志刷屏。

## C. 阶段1验收标准

1. 只在结构化剧情楼层挂载同层卡（`filter` 生效）。  
2. 同层卡能随 `during_streaming` 从“流式中”切到“已完成”。  
3. 同层卡仅显示当前楼层内容，不串层。  
4. 页面关闭/切聊天后不残留监听器（`pagehide -> unmount + eventClearAll`）。  
5. 对于 `<content>` 未闭合楼层，不出现模块文本污染正文。
