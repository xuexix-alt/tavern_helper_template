# 界面同层版开发文档

## 1. 项目目标

`界面同层版` 位于 `src/寒冬末日/界面同层版/`，它以 `src/流式最小Demo/` 为业务基底，迁入 `docs/UI/`
的 UI/UX 组织方式，形成更适合移动端和同层 iframe 的流式阅读工作台。

其中，当前可参考与迁移的 UI 模板原型位于 `docs/UI/`。

本次迁移坚持两个原则：

1. **业务逻辑不改向**：`generate`、楼层写回、transcript 重建、开局 payload、回滚/重生成功能全部沿用原 Demo。
2. **壳层体验重构**：把 `docs/UI` 的顶栏、抽屉、弹窗、状态概览和 HUD 语气迁到 Vue 结构中。

## 4. 迁移策略说明

### 4.1 为什么不直接复制 `docs/UI` 代码

`docs/UI` 是 React + Tailwind + Vite 原型，而仓库目标项目是 Vue + Webpack +
iframe 运行形态。直接搬运会引入额外框架切换成本，并破坏现有业务代码稳定性。

因此本次采用：

- **业务层**：直接复制并沿用 `流式最小Demo`
- **视觉与交互层**：按 `docs/UI` 的模块拆法，用 Vue 重建等价壳层
- **样式层**：复用原 Demo 已整理好的 token / HUD 主题体系，再向 `docs/UI` 的层级组织靠拢

### 4.2 为什么把控制项塞进弹窗

同层 iframe 需要优先保证 transcript 阅读面积；移动端又要避免一屏内出现过多切换控件。因此：

- 主界面只保留摘要和高频动作
- 中低频设置收进弹窗
- 角色信息走侧抽屉

这比把所有开关都铺在顶部更适合长文本阅读。

## 6. 验证建议

### 构建验证

在仓库根目录执行：

```bash
pnpm build
```

### 人工验证要点

1. 初次进入时，开局配置面板正常出现。
2. 生成开局后，界面切换到 transcript 主舞台。
3. 顶部按钮可以打开：阅读设置 / 人物面板；底部工具区可以展开：系统 / 地图面板。
4. transcript 内原有功能仍可使用：
   - 查看详情
   - 内联编辑用户输入
   - 删除回滚
   - assistant swipe
   - 回到最新
5. 切换主题、阅读密度、字体模式或 opening 折叠状态后，聊天变量中的 reader state 仍会持久化。
6. 移动端宽度下，角色抽屉改为底部上滑，不出现横向滚动。

## 6.1 文档同步说明
